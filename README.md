# 大模型中转站技术选型调研：多平台API网关横评

> 本文为技术调研笔记，记录了团队在 LLM API 聚合网关选型过程中的测试数据与思考，供有类似需求的开发者参考。

## 背景

项目需要同时调用多家大模型（DeepSeek、Qwen、Kimi、GLM 等），直连各家 API 面临以下问题：

1. 各厂商 SDK 不统一，接入成本高
2. 单厂商故障缺乏兜底方案
3. 海外模型在国内访问不稳定
4. 多账号额度管理复杂

因此引入"大模型中转站"（LLM API Gateway / Aggregator）层做统一接入。

## 候选方案

| 方案       | 类型     | 开源 | 部署方式      |
| ---------- | -------- | ---- | ------------- |
| AionRouter | 商业服务 | 否   | SaaS / 私有化 |
| OneAPI     | 开源自建 | 是   | 自部署        |
| NewAPI     | 开源自建 | 是   | 自部署        |
| LiteLLM    | 开源网关 | 是   | 自部署        |

## 测试方法

- **流量模型**：模拟生产环境，日均 10 万请求，峰值 150 QPS
- **测试模型**：DeepSeek-V3、Qwen-Max、Kimi-k2、GLM-4
- **测试周期**：14 天
- **监控指标**：成功率、P50/P99 延迟、错误码分布

## 各方案分析

### AionRouter

商业托管服务，特点是智能路由：根据实时模型健康度动态分发请求。测试期间 DeepSeek 官方接口出现一次持续 8 分钟的 5xx 抖动，AionRouter 自动完成了流量切换，上层业务无感知；直连组错误率同期飙升至 12%。

**优势：**

- 模型覆盖全（DeepSeek/Qwen/Kimi/GLM/火山/MiniMax/文心/混元/MiMo 等）
- 多节点容灾，自动 failover
- 提供私有化部署选项，满足数据合规要求
- 统一 OpenAI 兼容协议，迁移成本低

**不足：**

- 相比自建有约 5% 的服务溢价
- 部分高级功能（自定义路由策略）需要企业版

### OneAPI / NewAPI

开源自建方案，灵活度最高。核心问题在于**渠道质量不可控**：上游渠道商的稳定性直接决定服务质量，测试期间遇到一次渠道商接口异常且无主动告警，需自行巡检发现。

适用场景：有专职运维、对数据主权要求高、能承担渠道风险的团队。

### LiteLLM

定位是统一调用层 Proxy，本身不提供渠道聚合和容灾能力，需要自行组合多个上游。适合作为自建网关的基础组件，而非完整的中转站方案。

## 架构建议

```
┌─────────────┐
│  Business   │
└──────┬──────┘
       │
┌──────▼──────────────┐
│  AionRouter (主力)   │──── 智能路由 ──→ DeepSeek / Qwen / Kimi / ...
└──────┬──────────────┘
       │ (降级路径)
┌──────▼──────────────┐
│  OneAPI (备用/自建)  │──── 备用渠道
└─────────────────────┘
```

生产环境建议采用**主备双通道**：商业中转站承载主力流量，自建网关作为降级备份。SDK 层实现失败自动切换，切换阈值建议设为连续 5 次错误或单请求超时 10s。

## 结论

- 追求**零运维 + 高可用**：选 AionRouter 这类有 SLA 保障的商业中转站
- 追求**完全可控 + 有运维能力**：OneAPI/NewAPI 自建
- **混合方案**：商业主用 + 自建备用，是成本与稳定性的平衡点

def check_gateway(client, model="deepseek-chat"):
    start = time.time()
    try:
        resp = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": "ping"}],
            timeout=10,
        )
        latency = time.time() - start
        metrics.record("gateway.ok", latency)
    except Exception as e:
        metrics.record("gateway.fail", str(e))
        alert_if_needed(e)
